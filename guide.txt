----------------------------------------------------------------
1. ЧТО ЭТО ЗА ПРОЕКТ
----------------------------------------------------------------

Telegram-бот для моей мамы. Личный проект, не коммерческий.
Стек: Python 3.11+, aiogram 3.x, Pillow, aiohttp/requests, yt-dlp,
OpenRouter (бесплатные модели), OpenWeather, Vosk (STT).
Хостинг: Amvera (важно! сборка образа ограничена по весу и составу
системных пакетов).

Основные функции:
  • «Цвета дня» — картинка + текст по датам из colors_data.json
  • Аффирмации дня
  • Погода по городу мамы
  • «Спросить ИИ» — OpenRouter с перебором моделей и историей 20 сообщений
  • Скачивание видео из Instagram (yt-dlp)
  • Расписание рассылок (JobQueue): 8:00, 12:00, 18:00, 19:00, 22:00
  • Распознавание голосовых (Vosk)
  • Пересказ пересланных голосовых/текстов через ИИ

2. СТРУКТУРА ПРОЕКТА
----------------------------------------------------------------

mom_bot/
├── main.py                    # сборка бота, регистрация, планировщик
├── config.py                  # чтение variables.txt / env, БЕЗ секретов в коде
├── content.py                 # тексты: аффирмации, фразы, промпты
├── colors_data.json           # данные по датам
├── colors_repo.py             # доступ к colors_data.json
├── colors_image.py            # рендер картинки (Pillow)
├── keyboards.py               # все клавиатуры-категории
├── services/                  # внешние интеграции
│   ├── ai_service.py
│   ├── weather_service.py
│   ├── instagram_service.py
│   └── stt_service.py         # (голос → текст, сейчас переезжает на Vosk)
├── handlers/                  # обработчики сообщений/кнопок
│   ├── menu.py
│   ├── style.py
│   ├── ai.py
│   ├── weather.py
│   ├── instagram.py
│   ├── broadcast.py
│   └── router.py
├── variables.txt              # секреты (в .gitignore!)
├── requirements.txt
├── constraints.txt            # если нужен — для жёсткой фиксации версий
└── guide.txt                  # этот файл

Правило: новый функционал = новый handler (+ service, если это
внешняя интеграция). main.py растёт только на 1–3 строки регистрации.

3. СЕКРЕТЫ И БЕЗОПАСНОСТЬ
----------------------------------------------------------------

ЗАПРЕЩЕНО:
  ✗ писать токены/ключи в .py-файлах
  ✗ коммитить variables.txt
  ✗ логировать токены и ключи (даже в отладочных сообщениях)

РАЗРЕШЕНО И ОБЯЗАТЕЛЬНО:
  ✓ все секреты — только в variables.txt
  ✓ variables.txt — в .gitignore (проверь, что строка есть!)
  ✓ доступ к секретам — только через config.py
  ✓ в коде — os.getenv("TOKEN") и подобное

Если увидел в любом .py файле строку вида
  TOKEN = "123456:AA..."
— сразу скажи мне: «секрет в коде, надо вынести в config.py».

4. ОГРАНИЧЕНИЯ ПО БИБЛИОТЕКАМ (ВАЖНО!)
----------------------------------------------------------------

Хостинг Amvera не соберёт тяжёлые ML-пакеты. Уже один раз сборка
упала на ctranslate2 (зависимость faster-whisper).

ЧЁРНЫЙ СПИСОК (не ставить, не предлагать):
  ✗ faster-whisper
  ✗ ctranslate2
  ✗ torch / torchaudio / torchvision
  ✗ tensorflow
  ✗ transformers (в тяжёлых конфигурациях)
  ✗ openai-whisper
  ✗ любые библиотеки с CUDA-зависимостями

БЕЛЫЙ СПИСОК для локальных ML-задач:
  ✓ vosk          — STT, русская модель ~40–50 МБ
  ✓ piper-tts     — TTS, лёгкий, русские голоса
  ✓ silero-vad    — детектор речи, если понадобится
  ✓ что-то ещё — только после согласования со мной

Если сомневаешься в весе библиотеки — спроси меня ПЕРЕД тем,
как добавлять в requirements.txt.

Для STT: Vosk, модель ru, грузится ОДИН раз при старте,
держится в памяти, не пересоздаётся на каждый запрос.

----------------------------------------------------------------
5. СТИЛЬ КОДА
----------------------------------------------------------------

  • Python 3.11+
  • PEP8 без фанатизма
  • Докстринги и комментарии — на русском, кратко
  • Имена переменных — английские, но понятные (не a, b, c)
  • Никаких «магических» строк: текст для мамы — в content.py,
    названия кнопок — в keyboards.py, константы — сверху модуля
  • async/await везде, где есть I/O (aiogram, aiohttp, файлы)
  • Не блокировать event loop: тяжёлые вещи (рендер картинок,
    распознавание) — через asyncio.to_thread, если реально тяжело
  • Логирование через logging, формат:
      %(asctime)s | %(levelname)s | %(name)s | %(message)s
    Никогда не логировать содержимое variables.txt

----------------------------------------------------------------
6. ТЕКСТЫ ДЛЯ МАМЫ
----------------------------------------------------------------

Всё, что видит мама:
  • на русском
  • дружелюбно, тепло, можно с эмодзи
  • без технических терминов («ошибка API», «rate limit» и т.п.
    заменяем на «не получилось, попробуй позже»)
  • ошибки — мягкие, не пугающие

Все такие тексты хранить в content.py, не раскидывать по хендлерам.

----------------------------------------------------------------
7. КАК МЫ РАБОТАЕМ (ПРОЦЕСС)
----------------------------------------------------------------

1. Ты НЕ правишь код, пока я не сказал «делай».
   Сначала — план: какие файлы тронем, что изменим.
2. Одно изменение = один шаг. Не смешивай рефакторинг с фичей.
3. После правки — покажи:
     - какие файлы изменил
     - что именно изменилось (diff или итоговый блок)
     - как проверить (команда, шаг в боте, ожидаемый результат)
4. Если видишь проблему в моём коде — скажи, не правь молча.
5. Если чего-то не знаешь (например, куда Amvera разрешает писать
   файлы) — спроси, не выдумывай.
6. Перед добавлением новой зависимости — проверь её по разделу 4.
