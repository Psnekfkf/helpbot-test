# 🤖 Mom Assistant Bot

Тёплый и заботливый Telegram-бот для мамы с поддержкой ИИ. Меню
организовано по категориям, каждое действие доступно и кнопкой, и
командой.

## 📁 Структура проекта

├── content.py                # аффирмации, вопросы о настроении, пожелания, промпт для ИИ

## 🎛 Категории меню

| Категория | Кнопки внутри | Команды |
|---|---|---|
| 🎨 Стиль дня | Цвета дня, Цвета на завтра, Аффирмация | `/colors`, `/colors_tomorrow`, `/affirmation` |
| 🧠 Помощник | Спросить ИИ, Очистить историю | `/ai`, `/clear` |
| 🌤 Погода | — (действие сразу) | `/weather` |
| 📥 Медиа | Скачать из Инсты, Угадать песню | `/insta`, `/song` |

Общие команды: `/start`, `/menu`, `/help`. Плюс любое голосовое
сообщение работает как команда по ключевым словам или как пересказ
пересланного ГС — см. раздел «🎙 Голосовые команды и пересказ» ниже.

`/start` дополнительно шлёт картинку-баннер (`assets/welcome.png`) вместе
с приветствием. Если файл случайно не попал на хостинг — бот не упадёт,
просто пришлёт один текст (см. `handlers/menu.py`).

### 🎵 «Угадать песню» (Shazam)

Работает и по кнопке, и просто если прислать голосовое/аудио и оно НЕ
похоже на команду и НЕ распозналось как речь (см. следующий раздел про
голосовые команды — это единый механизм, Shazam там просто последний
шаг, если ничего другое не подошло).

1. Мама присылает голосовое или аудиофайл с отрывком песни (5–10+ сек).
2. Бот распознаёт трек через Shazam (библиотека `shazamio`) и присылает
   обложку с ссылками **в виде кнопок** (а не голым текстом — длинная
   ссылка с кучей символов выглядит подозрительно, будто вирус/фишинг):
   - **Shazam** и, как правило, **Apple Music** — точные ссылки (их
     отдаёт сам Shazam).
   - **Spotify** — точная ссылка на трек, если заданы
     `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET`; без них — ссылка на
     поиск в Spotify.
   - **YouTube** — первый результат поиска (через `yt-dlp`, без ключей).
   - **Яндекс.Музыка** — только ссылка на поиск: у сервиса нет
     публичного бесплатного API для точного совпадения.

   Кнопка, ведущая на поиск (а не точно на этот трек), помечена лупой 🔎.

### 🎙 Голосовые команды и пересказ (handlers/voice.py)

Любое голосовое/аудио сначала попадает в единый роутер, который решает,
что с ним делать:

1. **Переслано** (мама форварднула боту голосовое от подруги —
   тот самый длинный ГС на 5 минут) → распознаём речь и делаем
   **краткий пересказ** через ИИ (3–5 предложений с сутью, датами,
   просьбами) — `services/ai_service.py: summarize_text`.
2. **Явно нажата «🎵 Угадать песню»** → сразу Shazam, распознавание речи
   не запускается вообще.
3. **Обычное голосовое от мамы боту** → распознаём речь (локально,
   `faster-whisper`, без ключей) и ищем ключевое слово:
   - «погода» → 🌤 Погода
   - «цвет...» → 🎨 Цвета дня, «завтра» → 🎨 Цвета на завтра
   - «аффирмация» / «поддержи» / «вдохнови» → 💪 Аффирмация
   - «очисти» / «с чистого листа» → 🗑 Очистить историю
   - «инстаграм» / «инсту» / «рилс» → 📥 Скачать из Инсты
   - ничего не совпало, но текст есть → отдаём как обычный вопрос в ИИ
     (можно просто "поговорить" с ботом голосом)
   - речь не распознана вообще (пусто) → пробуем Shazam — вероятно,
     это музыка.

   Это **простой поиск подстроки** в распознанном тексте, а не
   настоящее понимание смысла — иногда будет случайное совпадение.
   Для голосового помощника мамы это ок: цена ошибки минимальна
   (откроется не тот раздел), а сложность в разы меньше настоящего NLU.

Распознавание речи — через `faster-whisper` (модель Whisper, но
локально, без сторонних API и ключей). При первом реальном голosovom
модель скачается один раз (нужен интернет на хостинге, но не нужен
никакой аккаунт) и дальше будет работать без обращений куда-либо.
Размер модели задаётся `STT_MODEL_SIZE` (по умолчанию `base`) — можно
поставить `tiny` для более слабого сервера или `small`/`medium` для
точности, если ресурсов достаточно.

### 🖥 ffmpeg — не системная зависимость

Telegram шлёт голосовые в OGG/Opus, а встроенный в `shazamio`
Rust-декодер (Symphonia) надёжно понимает только WAV/MP3 — OGG/Opus он
читает с ошибками (`end of stream`, "invalid mpeg audio header").
Поэтому перед распознаванием бот сам конвертирует присланный файл в
WAV.

Бинарник ffmpeg для этого берётся из pip-пакета `imageio-ffmpeg`
(он уже в `requirements.txt`) — при установке он сам скачивает готовый
статический ffmpeg. **Ни `apt-get`, ни root, ни Dockerfile для этого
не нужны** — обычного `pip install -r requirements.txt` достаточно на
любом хостинге, включая Amvera с обычным окружением "Python Pip" (без
Docker).

Если по какой-то причине `imageio-ffmpeg` не установится, код на
всякий случай пробует системный `ffmpeg` из PATH — но специально
что-то для этого ставить не нужно.

## 🚂 Деплой на Amvera

**Простой вариант (без Dockerfile)** — окружение "Python Pip":
всё уже работает из `requirements.txt`, включая `ffmpeg` через
`imageio-ffmpeg`. Ничего специально настраивать не нужно.

**Вариант с Dockerfile** (`Dockerfile` + `amvera.yaml` уже есть в
проекте) — не обязателен, но может быть удобен, если хочешь жёстко
закрепить версию Python (3.12 — важно из-за `shazamio-core`, у него
готовые wheel-сборки только до Python 3.12 включительно) и держать
системный `ffmpeg` как дополнительный запасной вариант. Если не
уверен — используй простой вариант без Docker, он проще и уже
достаточен.

### ⚠️ «Консоль» в панели Amvera — это НЕ shell

Если в интерфейсе Amvera есть кнопка вида «Консоль» / «TTY» с полем
«Введите текст, который хочешь отправить в консоль» — это подключение
к STDIN/STDOUT уже ЗАПУЩЕННОГО процесса бота, а не отдельный терминал.
`apt-get`, `pip install` и другие системные команды там **не
выполняются** — процесс питона просто получает эти строки как обычный
текст.

В этом проекте есть отдельная функция — консольный ввод в `main.py`
(`console_input_loop`): она читает то, что напечатано в STDIN бота, и
отправляет это МАМЕ в Telegram как обычное сообщение. Если попытаться
выполнить системную команду через ту же «консоль» Amvera — она уйдёт
не в систему, а мамочке в чат. Поэтому эта фича **выключена по
умолчанию**. Включить (если нужно слать сообщения маме прямо из
терминала при локальном запуске) — переменная окружения:
```
CONSOLE_INPUT_ENABLED=true
```

Также обрати внимание: `shazamio` тянет `shazamio-core` (написан на
Rust) — у него есть готовые wheel-пакеты под Python до 3.12
включительно, поэтому в `Dockerfile` этого проекта явно закреплён
`python:3.12-slim`. Если разворачиваешь без Dockerfile — держи Python
≤ 3.12, иначе pip попытается собирать `shazamio-core` из исходников
(нужен Rust-тулчейн).

## 🚀 Быстрый старт

```bash
git clone <ссылка на твой новый репозиторий>
cd mom_bot

python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate

pip install -r requirements.txt

cp variables.example.txt variables.txt
# впиши в variables.txt свои реальные TOKEN / ключи (см. ниже)

python main.py
```

## 📋 Переменные окружения

| Переменная | Описание | Пример |
|---|---|---|
| `TOKEN` | Telegram Bot Token | `123456789:ABC...` |
| `OPENROUTER_KEY` | API-ключ OpenRouter | `sk-or-v1-...` |
| `OPENWEATHER_KEY` | API-ключ OpenWeather | `c7da02ba...` |
| `CITY` | Город для погоды | `Rostov-na-Donu` |
| `MOM_CHAT_IDS` | Chat ID через запятую, кому шлём плановые сообщения | `549864131,8987266887` |
| `WATCH_USER_IDS` | Чьи ответы боту дублируются в канал | `549864131,8987266887` |
| `TARGET_CHANNEL_ID` | ID канала для пересылки | `-1004360677978` |
| `SPOTIFY_CLIENT_ID` *(необязательно)* | Client ID приложения Spotify — для точных ссылок на трек | `abcd1234...` |
| `SPOTIFY_CLIENT_SECRET` *(необязательно)* | Client Secret того же приложения | `abcd1234...` |
| `STT_MODEL_SIZE` *(необязательно)* | Размер модели распознавания речи: `tiny`/`base`/`small`/`medium` | `base` (по умолчанию) |

Spotify-ключи получаются на https://developer.spotify.com/dashboard →
Create app (Redirect URI можно указать любой, например
`http://localhost` — он не используется для Client Credentials Flow).
Без этих двух переменных бот работает как обычно, просто вместо ссылки
на конкретный трек в Spotify даёт ссылку на поиск.

`STT_MODEL_SIZE` ключей/аккаунтов не требует вообще — модель скачивается
один раз при первом голосовом сообщении. `tiny` — быстрее и легче для
слабого сервера, `small`/`medium` — точнее, но медленнее и требуют
больше памяти.

Все переменные — в `variables.txt` **локально** (файл в `.gitignore`,
никогда не коммить его). На хостинге задавай их через настоящие
переменные окружения — они всегда имеют приоритет над файлом.

## ⚠️ Важно про безопасность

1. **Никогда** не коммить `variables.txt` с реальными ключами.
2. Если ключ/токен когда-либо публиковался (в открытом репозитории,
   переписке, скриншоте) — считай его скомпрометированным и
   перевыпусти новый.
3. На проде используй переменные окружения хостинга, а не файл.

## 🧠 Система ИИ

- **API**: OpenRouter (бесплатные модели)
- Автопереключение между моделями при недоступности/лимите
- История последних 20 сообщений на пользователя (в памяти процесса —
  сбрасывается при перезапуске)

## 🔧 Как добавить новую кнопку/категорию

1. Добавь текст кнопки и, если нужно, новую категорию в `keyboards.py`.
2. Напиши хендлер в подходящем файле `handlers/` (или создай новый).
3. Зарегистрируй кнопку в `ACTION_ROUTES` или `CATEGORY_ROUTES` в
   `handlers/router.py`.
4. При желании добавь команду в `main.py` (`CommandHandler`).

## 📝 Логирование

Все события логируются с временной меткой: запуск бота, переключение
моделей ИИ, ошибки API, отправленные сообщения.
